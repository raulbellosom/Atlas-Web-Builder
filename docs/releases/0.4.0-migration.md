# Migración de Atlas 0.3.5 a 0.4.0

0.4.0 es una versión minor de la serie 0.x: introduce API opcional y una corrección observable de visibilidad. No se publica durante la preparación. No requiere migración del documento ni cambiar el catálogo Website 0.3.5: la versión de runtime no es la versión del contrato de plantilla.

## API y comportamiento

- Los 139 exports anteriores continúan disponibles. Se añade `editorCapabilitiesVersion`, con valor 1. `version` y getVersion() devuelven 0.4.0.
- Un editor sin capabilities conserva su uso genérico; React y ReactDOM siguen siendo peers >=18. No se añaden dependencias runtime ni @runly/ui.
- La prop opcional capabilities exige schemaVersion 1. No relaja validadores de servidor. El perfil Website v2 protege las propiedades que no pueden guardarse en ese contrato.
- Las páginas nuevas usan public y el selector sólo permite public/private. Estado editorial draft se administra en el host; no se cambia silenciosamente la visibilidad de un documento existente.
- No se reescriben props, IDs, regiones ni SEO al cargar. Website v2 continúa rechazando efectos y SEO no portables. Esos valores necesitan migración de contrato explícita, no eliminación.

## Consumidores Runly

ERP debe actualizar sus tres pins: apps/api, apps/desktop y packages/website-blocks. Su builder de runtime público debe admitir explícitamente 0.4.0; debe conservar 0.3.5 para rollback. Se revalidan runtime cliente y SSR juntos para no mezclar hashes de hidratación.

Hub necesita el perfil y el guard de Fase 0.5, el pin directo 0.4.0 y un override pnpm exacto 0.4.0 para el Atlas transitivo del paquete compartido website-blocks. Así se evita mezclar 0.3.5 y 0.4.0 sin republicar innecesariamente todos los paquetes compartidos. Esta combinación debe probarse contra el tarball y luego contra los bytes del registro.

Hasta que el paquete instalado exponga editorCapabilitiesVersion=1, Hub bloquea la edición sin modificar documentos ni retirar defensas. No sustituir archivos de node_modules ni cambiar el lock a una ruta temporal.

Ver [el contrato API 1](../contracts/WEBSITE_EDITOR_CAPABILITIES_V1.md). Las instrucciones exactas de distribución y rollback se mantienen en el informe de Fase 0.6 del repositorio; no se ejecutan sin autorización.
